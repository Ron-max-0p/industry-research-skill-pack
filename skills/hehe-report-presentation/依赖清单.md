# 商业报告呈现：依赖与首次运行

依赖安装在实际运行脚本的电脑或服务器上。若 Agent 在云端完成制作，收件人只需能打开 HTML、PDF 或 PPTX 的软件，无须在自己的电脑安装 Python。

## 按交付格式准备

| 任务 | 所需环境 | 用途 |
|---|---|---|
| 从 JSON 页面源生成 HTML | Python 3，使用标准库 | `scripts/render_report.py` 生成报告文件 |
| 从 Markdown 直接生成下拉 HTML | Python + `markdown` + `beautifulsoup4` | 解析段落、表格、脚注、标题和本地图片，自动生成侧栏目录；无需分页脚本或其他 Skill |
| 检查 HTML、导出并核对 PDF | Python + `playwright` + `pymupdf` + Chrome 或 Chromium | `scripts/export_and_check.py` 读取实际页面、截图、导出及核对 PDF |
| 生成可编辑 PPTX | Python + `playwright` + `python-pptx` + Chrome 或 Chromium | `scripts/export_pptx.py` 把本 Skill 分页 HTML 的布局转为 PPT 原生对象 |
| 验收 PPT 的实际排版与编辑 | PowerPoint 或 LibreOffice，以及报告所用字体 | 打开、修改、保存重开并导出预览；生成 PPTX 本身不要求安装 Office |

优先复用已有 Python、浏览器和办公软件。新建环境选择各依赖共同支持的 Python 版本，可优先检查 Python 3.11 及以上版本是否有对应安装包；只补本次交付所缺的依赖。无需显卡、本地大模型或付费 PPT 云服务。新增体积主要来自浏览器和办公软件，已有可用软件时可复用。

## 运行条件不足时

只补本次需要的环境，安装受限时使用现有可用路径：

- 缺 Markdown 解析包：将已定稿的章节、完整段落、表格和链接转成 HTML 正文，按 [HTML制作与核验](references/HTML制作与核验.md) 放入 `canvas: scroll` 的 JSON 页面源；现有生成器只需 Python 标准库，仍带侧栏目录。逐项对照原稿核验内容，不用摘要替代正文。
- 缺 Python：直接使用 `assets/report.html` 及随包样式填写报告；下拉版同时接入 `assets/scroll-sidebar.css` 和 `assets/scroll-sidebar.js`，将资源内嵌后检查目录和正文。
- 缺浏览器或自动化包：先完成 HTML；PDF 和 PPT 用已有可用工具继续制作，无法制作时写明实际缺项及需要的环境。生成器自动隐藏不存在的 PDF 下载入口，也可用 `--no-pdf` 主动隐藏；技术检查注明未实际验证的部分。

这些条件不阻塞上游研究和 Markdown 定稿。已约定的 PDF／PPT 不因交付 HTML 自动视为完成。

## 安装与浏览器路径

下列命令中的 `python` 须指向本项目实际运行脚本的解释器。按任务选择安装，已有可用版本无需重复安装或升级。

HTML/PDF 检查与导出：

```sh
python -m pip install playwright pymupdf
```

Markdown 直接输入另需两个文本解析包；已有可用版本无需重复安装：

```sh
python -m pip install markdown beautifulsoup4
```

可编辑 PPTX 生成：

```sh
python -m pip install playwright python-pptx
```

`python-pptx` 所需的 `lxml`、Pillow 等依赖由 pip 一并安装。PDF 核验中的 `import fitz` 对应安装包 `pymupdf`，不要误装名称为 `fitz` 的其他包。

先查找已有 Chrome 或 Chromium 的可执行文件，把实际路径传给导出命令的 `--browser`。当前脚本要求显式提供此参数，并不自动发现浏览器。若没有可用浏览器，只下载 Chromium：

```sh
python -m playwright install chromium
python -c "from playwright.sync_api import sync_playwright; p=sync_playwright().start(); print(p.chromium.executable_path); p.stop()"
```

第二条命令输出可供 `--browser` 使用的路径。Linux 若缺浏览器系统库，再按 [Playwright 官方安装说明](https://playwright.dev/python/docs/browsers#install-system-dependencies) 补齐所缺项。首次下载需要联网；依赖与报告素材齐备后，本 Skill 的本地转换流程可离线运行。

## 首次运行检查

由 Agent 在首次使用或运行环境变化时执行：

1. 确认 Python 版本及路径，按上表检查所需包能否导入。常用模块名为 `playwright.sync_api`、`pptx`、`fitz`，分别对应 `playwright`、`python-pptx`、`pymupdf`。
2. 确认 `--browser` 指向有效文件，并能用该浏览器打开本地报告。用一页真实内容检查中文、图表和 PDF 输出，再展开整稿。
3. 确认制作与验收环境都有报告字体。当前 PPT 脚本明确使用微软雅黑（`Microsoft YaHei`）；若环境没有该字体，应取得可用字体，或将 HTML 与 PPT 脚本中的字体同步改为实际安装的中文字体，再核对换行和溢出。脚本目前没有字体自动替换配置。
4. PPT 按 [可编辑PPT交付.md](references/可编辑PPT交付.md) 完成办公软件中的实际编辑与渲染检查。没有 PowerPoint 或 LibreOffice 时仍可生成 PPTX，但须注明“尚未完成办公软件中的实际打开、编辑与渲染核验”。Windows COM 自动化另需 `pywin32`；仅采用该验收方式时安装，普通生成和手动验收均不需要。

安装位置、实际 Python/浏览器及检查结果记在项目执行记录中。

依赖用途与安装方式依据：[python-pptx](https://pypi.org/project/python-pptx/)、[Playwright Python](https://playwright.dev/python/docs/library)、[PyMuPDF](https://pypi.org/project/pymupdf/)。
