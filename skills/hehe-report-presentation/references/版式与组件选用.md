# 商业版式与组件选用

## 依据关系选择完整实例

先识别内容关系，再按下表选图，最后安排正文；原稿的段落数量不决定版式。材料具备关系时优先采用对应图式。表格负责精确查阅和同维度比较，连续正文负责展开推理。页码指 `assets/business_layouts.json` 的八页教学示范；读取该页字段并替换为项目完整内容。基础图表、样本、报价等对象另见 `assets/example.json`。

| 内容关系与用途 | 结构及实例 | 输入材料与安排 |
|---|---|---|
| 谁付款、谁交付、谁反馈 | 资金流、数据流或角色网络图 | 节点写主体及职责，连线写付款、交付物或反馈内容；不同流向用线型和文字区分；未确认的交易关系不补画 |
| 条件决定不同选择 | 条件分支图或决策树 | 起点说明决策，分支写明确条件和对应结果，完整理由靠近分支；不是把几个方案并列成卡片 |
| 层级、产业链与上下游依赖 | 结构图或产业链图 | 用包含、层级及连线表达关系；没有规模数据时只表达结构，不暗示比例 |
| 项目概览、核心论述与配套说明 | `briefing`，示范第1页 | 主区依次解释需求与解决方案，侧区交代成果和执行条件；主次栏宽跟随内容，完整计划书概览仍覆盖需求、方法和交付 |
| 多业务共同影响一个决定 | `branch_merge`，第2页 | 各分支保留对象及完整解释，统一汇入共同评价；只有材料支持汇合关系时使用箭头 |
| 推导或逐步形成判断 | `analysis_path`，第3页 | 各阶段给出输入、处理及结果，完整解释放在对应阶段；阶段过多时改纵向或按完整子问题拆分 |
| 方法执行、团队与客户协作 | `swimlane`，第4页 | 横向为阶段，纵向为角色或任务，交叉处写谁做什么；时间和确认事项明确到实际节点 |
| 工作持续时间及阶段交付 | `gantt`，第5页 | 已知起止、工作和成果；条长只表达提供的时间范围，交付说明留在同一行；只有日期节点时使用 `timeline` |
| 用户行为、困难与改进 | `journey`，第6页 | 以实际阶段为列，把行为、痛点和建议逐项对应；发生条件与解释完整保留在单元格中 |
| 多对象或分组的数量差异 | `split`＋`chart: hbar`＋`prose`，第7页 | 类别名称、分组、数值、单位、基数和来源；图中直接标数，旁边展开差距及含义 |
| 起点、增减项与最终结果 | `chart: waterfall`＋解释，第8页 | 起点、各增减项、合计及统一口径；先核对勾稽，再说明哪些成本或收益改变结果 |
| 同维度比较、报价及交付清单 | `table` | 行维度、列对象、同口径内容；明细报价含数量、单位、单价和合计，可独立抽取；交付物另列文件及用途 |
| 连续时间变化、总量构成、样本分布 | `chart: line/stacked/bar` 或分布图 | 同口径时间序列、共同分母或个体观测值；趋势解释与图相邻，构成分类互斥，预测区段明确标注；仅有均值时不补造分布 |
| 市场测算、财务计算 | 计算关系图＋必要变量明细＋解释 | 因子、运算符和结果连成可读路径，名称、单位及条件同页呈现；变量表提供精确取值，不能单独代替计算关系 |
| 样本说明、人员配置 | `metrics` 或责任图＋说明 | 数字有群体、单位和原始依据；正式样本与补访分别说明，角色名称旁保留职责 |
| 连续论证、定义与条件解释 | `prose`、`briefing`、非等宽 `split` | 先检查其中有无过程、因果或结构可画；无独立图形关系时按自然段组织，并在图形方案中写明正文承担的作用 |

## 排版到实际阅读的处理

**主次阅读区**：长论述优先取得宽度，辅助说明使用较窄侧栏。两栏各自讲完整内容；侧栏过长时改为上下阅读。一个视觉重点足以建立主次，底色、框线与巨型数字不应同时争夺注意。

**分支、推导与泳道**：箭头表达顺序或汇合，行列对齐表达比较与分工。图内直接放完整解释，使读者沿关系读到理由；不另抄一遍同义摘要。阶段超过横向容量时先改变方向，按主题拆页时保留各阶段的完整输入与产出。

**比较表与旅程**：维度列名称完整，解释列取得足够宽度；数字右对齐，解释左对齐。长表按完整行分组并重复表头。`swimlane` 与 `journey` 在9:16和A4中按阶段纵向展开，每阶段保留相同的角色或研究维度；其他宽表根据需要改为纵向阅读，不将多列等比例压成细长文字条。

**图表与解读**：类别名称和直接数值标注靠近数据，单位与统计基数靠近图标题，来源放图底。解释沿用图中对象名称和顺序。条形从零线起算；组间差、变化率与百分点分别表述。主次比例按实际文字长度调整。

**周期与成果**：时间条呈现工作的持续和重叠，节点写具体交付及确认内容。已有逐周安排可以逐行表示；尚无起止资料时先补排期，不能凭版式制造并行关系。内部工时核算与对客周期分别安排。

同主题连续表格可以保持一致。不同用途的页面分别采用相应结构，用色彩、字级、网格维持整稿统一。页面数由主题与实测容量决定，不按组件数量机械拆页。

## 组件与数据接口

页面使用 `blocks` 或项目专用 `body`，二者择一。基础对象由 `scripts/components.py` 渲染；主次阅读、分支汇合、推导、泳道、甘特、旅程及新增图表由 `scripts/business_components.py` 渲染，样式在 `assets/business.css`。完整字段以两个示例 JSON 为准。

每个正文页或下拉模块的 `visual_plan` 依 [图形优先与生成检查.md](图形优先与生成检查.md) 记录。现成组件不适合时，使用 SVG 或 HTML/CSS 制作专用图式；不能因为组件库没有该图，就退回大段文字或普通表格。

图表提供分组柱形、堆积柱形、折线、横向条形与瀑布。横向条形支持有限正负数；瀑布支持累计值非负的收入、成本和利润构成，合计须等于前序增减结果。跨零累计、散点等关系使用专用图表实现，仍按原数据和关系制作；需要 PPT 时配套可编辑对象。
