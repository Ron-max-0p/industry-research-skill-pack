# HTML 制作与核验

## 页面源

下拉报告可直接使用 `.md`，无需 `hehe-report-writing` 或中间分页稿。生成器保留正文、表格、引用和标题锚点，按一级、二级标题组织自然高度的章节，侧栏同时收录内层小节；不补造副标题。本地图片嵌入 HTML；网络图片先下载并改为本地路径。相对附件链接按输出位置重定位，移交报告时同时携带对应附件。

顶层字段：`title`、`footer`、`pdf_file`、`slides`，以及 `canvas`（`16:9`、`9:16`、`A4`、`scroll`）和 `theme`（`blue`、`editorial`、`brief`）。省略画布与风格时沿用16:9蓝白。

每页或模块包括：

- `kind`：`cover`、`toc`、`chapter`、`content` 或 `back`。
- `section`、`title`、`lead`：章节标识、主标题、完整副标题；翻页报告主副标题必填，下拉正文按原稿层级组织，`lead` 可省略。
- `blocks` 或 `body`：前者按 `assets/example.json` 与 `assets/business_layouts.json` 使用标准组件，后者为已完成编排的正文 HTML。
- `layout`、`purpose`、`source`：内部说明版式、用途和正文来源，不显示在对客页面。
- `visual_plan`：正文页或下拉模块的关系、图式、目标对象与完整解释位置；字段及专用图形标注见 [图形优先与生成检查.md](图形优先与生成检查.md)。标准组件可设置 `id` 供方案定位，不改变其内容和布局。

完整段落和表格使用 `data-source` 或另附对应表连接原稿。图形摘要与原文区分；正文核对以输入原稿为基线。项目必要样式放顶层 `extra_css`，避免在单页内注入全局样式。模式样式由 `assets/modes.css` 管理，商业阅读结构由 `assets/business.css` 管理；新增项目图形先检查不同画布中的排法。

## 生成与导出

```text
python scripts/render_report.py 页面源_CO.json 报告_CO.html
python scripts/render_report.py 文本报告_CO.md 下拉报告_CO.html
python scripts/export_and_check.py 报告_CO.html --browser "本机Chrome或Chromium的路径" --out 核查_CO
```

运行前按 [依赖清单.md](../依赖清单.md) 准备对应环境并取得浏览器实际路径。输出默认不覆盖；明确迭代当前候选时使用 `--replace`。生成 HTML 时仅为已存在的本地 PDF 显示下载入口；加 `--no-pdf` 可主动隐藏入口。导出脚本成功生成并通过核验后，会自动更新 HTML 中的 PDF 下载入口。

新设计的 JSON 页面源默认先检查 `visual_plan` 与实际对象，不通过时不写出文件。直接 Markdown 转换保留原有图文；历史 JSON 原样重渲染可加 `--preserve-layout`。两种原样转换都保留基础交付能力，不作为图形优化完成的依据；需要视觉编排时按上一节制作带方案的 JSON，`canvas: scroll` 仍不需要分页脚本。

HTML 是离线单文件，带翻页或章节定位、目录及全屏。Markdown 输入默认查找与输出 HTML 同名的 PDF；JSON 输入按 `pdf_file` 查找，路径相对于输出 HTML。导出脚本生成同名 PDF 并更新链接；交付时 HTML 与 PDF 一起提供。分页模式采用整张固定画布缩放，正文在确定画布时重新布局。下拉模式采用自然高度和窄屏重排。

下拉侧栏的样式和交互分别由 `assets/scroll-sidebar.css`、`assets/scroll-sidebar.js` 管理，只在下拉模式加载。验收时实际点击章节和小节、上下滚动检查当前位置提示、切换窄屏并开关目录，再检查打印时导航隐藏和正文恢复全宽；链接应能离线定位，中文或重名标题使用唯一锚点。

导出脚本启用背景色、关闭浏览器页眉页脚，并使用 CSS 纸张尺寸。16:9、9:16、A4 分页版一页对应一页 PDF；下拉报告按 A4 自然分页，单独设置页边距、重复表头和图文分段。

## 检查分工

生成前检查图形方案及实际对象；导出检查覆盖页面边界、文字容器、正文与页脚相交、页面数与尺寸、导航、离线加载、窄窗口比例及 DOM 正文在 PDF 中的保留。大段空白作为人工复核线索，不据此自动加图或拆合页。

独立内容核对从原 MD、数据或其他输入逐项检查，不能只比较生成器与自己的输出。图形增加标签后，需要核对完整句子仍按原意、原序存在，表格和图表数字沿用原始口径。

视觉检查先看全稿缩略图，再看实际尺寸页面。检查清晰阅读、完整词组换行、图形关系、表格列宽和版式节奏；字体、颜色和行距在不同格式中重新查看。发现问题后修改页面源或组件并重新生成受影响格式。

内部记录包含输入文件及哈希、关键要求对应操作、内容核对结果、实际查看页码、问题与处理、技术结果。技术检查完成与用户认可风格分开记录。
