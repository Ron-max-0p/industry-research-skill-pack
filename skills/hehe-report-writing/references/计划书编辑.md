# 研究计划书编辑

计划书面向尚在选择研究服务或确认项目的客户。先解释其商业困境和决策，再说明研究如何帮助。已有项目策划负责研究设计，本模块负责把设计写充分、检查内部对应。

## 客户需求理解

先形成完整商业背景：委托方的企业类型与已有能力、拟进入的产品业务、目标市场和采购群体、现有基础及尚待解决的问题、立项目的与希望取得的答案。只使用已知背景；模拟设定集中注明，缺失事实不以“知名、领先”等赞誉补齐。

同章按“背景与目标 → 需求拆解 → 研究价值与回答深度”递进。项目总览串起委托方、目标、需求、总体思路、研究模块、对应方法与可交付成果。各页标题和正文回答各自任务，不把预算、资料索取与需求理解混排。

私下委托中的情绪、部门意见和个人评价不直接写入管理层方案；保留有用事实，把分歧转为公司需要研究的具体问题。先讲公司发展目标及研究要支持的决定，再讨论已有测试或反馈，不能让提出委托的部门立场替代公司目标。

从客户处境展开：为什么现在需要研究，准备作什么决定，哪些不确定性阻碍决定，答清后将如何使用。把“了解用户需求”具体化为产品选择、购买情境、使用障碍或服务调整等材料已明确的问题。

按商业问题分块，每块写清客户要决定什么，再对应可研究的问题。不要把“开展访谈”“建立模型”当作客户需求。需求评估随后说明哪些能深入回答、哪些只能形成方向或情景，以及影响回答深度的关键条件。

需求评估只保留影响回答深度的关键条件及其业务影响；具体资料清单、提供责任人、日期与场地配合统一写入项目协作或执行安排，并在必要处引用。有缺项时写“需确认……”及它影响哪一项研究，不自行承诺时间或把整份方案停住。

## 研究思路与方法

总体思路说明先解决哪类问题，结果如何影响后续研究，最后怎样形成建议。方法章节展开对象、范围、执行方式、分析方式与对应产出。例如访谈购买者用于理解采购过程，渠道访谈用于了解销售及服务条件；不能只写“定性定量结合，多维交叉验证”。

研究框架展现最终要回答的板块及其关系；方法讲怎样取得和分析材料；最终报告框架讲成果如何组织。三者衔接即可，不重复粘贴客户需求或把方法清单当框架。

## 交付、执行与商务一致性

逐项核对：客户问题 → 研究方法与对象 → 能形成的回答 → 交付材料。重要需求没有对应方法或成果时指出缺项，不靠补一句“全面分析”完成闭合。

客户版排期写准备、招募、预试、正式执行、补充研究、分析、反馈及交付的安排。具体确认节点交代日期、研究方提交什么、客户确认或提供什么、完成标准；沿用已核定的日历。内部排人和成本推算留在执行或测算附件。

报价与交付内容可以分别阅读或抽取。报价数字、数量、人天、费率、硬成本、税费与总额按原始测算核对；发现算术或口径冲突先查依据。编辑不通过削减工作或擅改单价凑总额。

正文说明实际合作安排，例如“客户提供三家门店联系人并确认可到店日期”；不用“客户输入到位，团队才能收口”替代。预期产出写成报告、比较表、方案或试点设计的内容和用途，不承诺研究必然带来收入增长或成本下降。
