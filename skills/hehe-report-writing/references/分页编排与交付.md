# Research Report Script

## 在 hehe-report-writing 中执行

原报告分页脚本的完整正文与适用任务已并入本模块，无需另装脚本 Skill。下文的 “this skill” 指本分页模块，F 指用户；按所选模式完整读取对应参考、逐页格式和分页交接要求。

原入口的适用任务：Generate Markdown report scripts for research projects. Use when the user asks to create a report framework, module script, page-by-page script, PPT script, or integrated research report script from industry research, user research, company research, or mixed research evidence. Supports four modes: industry, user, company, and integrated. Produces Markdown only, not PPT.

专业写作、润色与审校继续执行主 Skill；已有成熟正文可直接进入分页编排，局部表达问题按需要修订。按原文中 Version Discipline 进入制作前，先完成主 Skill 的内容质检；不把“不追求措辞完美”理解为跳过完整表达。

对照输入确认完整论述、数据、表格、来源和必要条件在脚本中的去向；需要修改或暂不进入成品的内容记录到对应页面。未解决的问题写明页面和返回环节，其余具备条件的内容继续编排。

## Purpose

Create a Markdown report script that can enter PPT production.

Use this skill after research analysis has produced enough evidence, charts, tables, interview findings, survey outputs, or module conclusions; an approved research proposal can enter with its design, scope, schedule and deliverables instead of findings.

Do not use it to do primary research, collect data, clean survey data, or build PPT.

## Mode Selection

For findings reports, select one mode before writing. For existing proposals, use the pagination reference and schema directly, preserving the approved proposal structure:

| Mode | Use when | Read |
|---|---|---|
| `industry` | Industry module script | `分页编排/industry.md` |
| `user` | User research module script | `分页编排/user.md` |
| `company` | Company research module script | `分页编排/company.md` |
| `integrated` | Integrated report script from multiple modules | `分页编排/integrated.md` |

If the task is a pure survey report based on a survey analysis workbook and Excel chart library, use `user` mode and follow the survey-heavy rules in `分页编排/user.md`. Do not require a separate survey-report helper; legacy survey page scripts may be consumed as ordinary input evidence.

Always use `分页编排/page-script-schema.md` as the output schema.

For pagination, read [分页与内容交接](分页编排/分页与内容交接.md). An existing proposal can also enter through this reference: preserve its approved research design and chapters, rather than imposing a findings-report structure. Scrolling HTML uses continuous prose and does not need this pagination step.

## Required Inputs

Use what exists; do not block V1 just because not all inputs are ready.

Minimum:
- project goal or project control file;
- available evidence files;
- target reader or use case;
- expected output type: module script or integrated report script.

Preferred:
- project control file;
- route card or module status card;
- analysis drafts;
- chart library or chart list;
- confirmed conclusions;
- known evidence gaps;
- F feedback or required storyline.

## Output Rules

Generate one Markdown file.

Recommended names:

```text
YYYYMMDD_project_industry_report_script_v0.1_CO.md
YYYYMMDD_project_user_report_script_v0.1_CO.md
YYYYMMDD_project_company_report_script_v0.1_CO.md
YYYYMMDD_project_integrated_report_script_v0.1_CO.md
```

Do not overwrite old versions.

## Standard Structure

Use the following structure for a complete script; omit empty gap/question sections. For proposals, evidence maps refer to supplied design inputs and assumptions, not future research findings:

1. Version info;
2. Input files;
3. Report goal and reader;
4. Evidence boundary;
5. Report framework;
6. Page-by-page script;
7. Evidence map;
8. Chart plan;
9. Gap and rework list;
10. Questions for F;
11. PPT readiness judgment.

## Page Script Fields

Each content page must include:

| Field | Requirement |
|---|---|
| Page number | Temporary page number |
| Section | Chapter or module |
| Page role | overview / evidence / comparison / mechanism / recommendation / transition |
| Main title | Required on content pages: identify the subject and analytical angle, e.g. 行业趋势—用户层面 |
| Subtitle | Required on content pages: tell the page’s story or core judgment in a complete statement, supported by the body; for proposals, state the planned approach or intended answer |
| Body | Key facts, interpretation, implication |
| Chart design | Chart type, data source, layout |
| Evidence | File, table, chart, interview, survey item, source |
| Boundary | base, scope, sample, time, geography, verification status |
| Page status | ready for PPT / revise script / add evidence / confirm with F / delete |

## Version Discipline

Version by actual revisions. Move to production when the storyline, required content and sources are ready; a version number alone does not establish readiness.

Do not chase perfect wording in Markdown. Once the script has a clear storyline, usable evidence, and no P0 blockers, recommend entering PPT.

## Quality Gates

- The report is not a file summary or question-by-question dump.
- Each page has one job.
- Every conclusion maps to evidence or is marked pending verification.
- Weak evidence is not promoted into a formal conclusion.
- Cross-module contradictions are listed, not hidden.
- The script shows what should not enter PPT.
- Each core page records the evidence-ledger reference or an explicit pending-verification label; unresolved figures cannot become headline numbers or executive-summary support.
- Separate facts, self-reported claims, research estimates, inferences, and scenarios; estimates disclose assumptions and do not masquerade as market facts.
- For each quantitative page, state a compact data contract: metric, population/denominator, time, region, unit, source or ledger key, and permitted conclusion; place full lineage in the appendix or evidence ledger.

## Presentation handoff

An approved page script can be passed to `hehe-report-presentation` for paged HTML, PDF or editable PPTX. Pass the complete body, main title, required subtitle, chart data, sources and intended canvas. Its renderer realizes the page design; it does not replace the research or shorten the approved text. A scrolling report can go directly from professional prose to presentation without this pagination step.

## Final Response

When reporting back to F:
- mode used;
- output path;
- pages or sections drafted;
- P0 blockers;
- whether it can enter PPT.
