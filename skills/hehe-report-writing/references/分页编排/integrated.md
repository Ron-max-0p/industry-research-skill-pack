# Integrated Mode

Use for 综合研究报告脚本.

This mode consumes module scripts from 行研、用研、企研 and turns them into one report path.

## Inputs

Preferred inputs:
- project control file;
- route card;
- 行研报告脚本;
- 用研报告脚本;
- 企研报告脚本 if enabled;
- confirmed conclusions;
- F总 feedback;
- final deliverable requirements.

## Integration Logic

Do not paste module scripts together.

Build a cross-module storyline:

1. Business decision;
2. market or context;
3. user evidence;
4. company or competitor evidence if needed;
5. synthesis;
6. recommendation;
7. risks and next actions.

## Page Types

| Page type | Purpose |
|---|---|
| 执行摘要页 | State the answer and recommendation |
| 决策问题页 | Define what the report is solving |
| 市场背景页 | Use 行研 only as needed |
| 用户证据页 | Use 用研 to validate demand and prioritization |
| 竞争/企业页 | Use 行研/企研 to explain external constraints |
| 交叉验证页 | Show where modules confirm or conflict |
| 策略建议页 | Translate evidence into action |
| 风险与待验证页 | Keep uncertain claims out of final conclusion |

## Evidence Rules

- Every recommendation must map to at least one evidence source.
- Cross-module conflicts must be listed and marked `【待核实】`.
- Do not let one weak module dominate the final recommendation.
- If a module is missing, state the limitation.
- Preserve source labels: `[事实]`, `[推断]`, `[待核实]`, `[模型知识]`.

## Required Output Emphasis

Include:
- module evidence map;
- which module supports each recommendation;
- missing module or evidence gaps;
- final PPT readiness.

## Common P0 Blockers

- no confirmed report objective;
- module conclusions contradict and no decision rule is given;
- recommendation has no evidence;
- key module script missing;
- final page asks for action not supported by prior narrative.
