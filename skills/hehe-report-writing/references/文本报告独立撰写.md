# 文本报告独立撰写

用于根据用户已有资料、笔记、数据和分析，新写一份可独立阅读的 Markdown 文本报告，适合简单、小型报告。无需其他研究 Skill 或完整项目开题。已有成型报告走主 Skill 的润色或审校模式；行研总入口及专项已有的成文流程不调用本模块。

写作沿用主 Skill 的专业编辑、商业表达、去AI味和事实保留规则。本模块只补充从材料到完整文本报告的组织方法。

## 1. 明确报告用途和可用材料

从用户要求中确认读者、要说明的问题或支持的决定、研究对象、时间范围、篇幅及文件位置。已有约定直接沿用；缺少会改变主线的条件再集中询问，不另建开题文件。

通读现有材料，整理“可写的判断—支持事实、计算或案例—来源位置—适用条件—拟放章节”。短报告可在现有笔记中标注，已有材料索引直接复用。区分事实、计算、推断、情景与待核实内容；信息缺口只限制相关判断，其余内容继续成文。需补采或重新计算的问题交回相应研究环节。

## 2. 组织主线与章节

用一句话明确全篇主要意思，再按读者理解问题的顺序安排章节。可以从现实与案例进入规模、结构和机制，也可先给结论再展开依据；不按材料文件或 Skill 名称顺序拼贴。

为每章明确要说明的内容、主要判断、关键论据、案例或图表，以及与前后章的联系；反例和条件放在它们实际影响的判断旁。小报告可以将这些安排直接体现在提纲中，无需另交章节卡。

概念与共同口径集中说明，后文沿用。分类或框架须服务后续分析；无实际用途的框架删去。面向不同读者时，按实际需要分别解释同一发现对其位置、机会或选择的意义。

## 3. 写出分析与解释

围绕每章主要判断展开依据、机制、比较和读者含义，不能仅列资料。用材料中的具体案例或数据解释抽象关系；材料没有提供的事实不以占位案例补齐。

- 数字交代对象、时间、单位、分母和来源；区分收入、交易额、利润、回款，以及注册、活跃、付费等不同指标。
- 案例保留主体、时间、发生内容及出处。已有编码或统计可按原口径使用，明确“本次案例中”等范围；个案不自动代表总体。
- 同一事实在最有用的位置展开，保留主出处和必要的独立来源；重复说明合并。不同口径结果并列解释，不直接平均。
- 计算与情景保留必要公式、参数、条件及工作表入口。复杂底表可放附件，正文仍说明结果与意义。
- 来源或结论冲突先核对原材料；尚未解决且影响判断时，说明实质差异及当前可判断范围，不用模糊措辞抹平。
- 图表与正文沿用相同对象、环节、术语和编号，每张图表配必要读法或发现，保留数据或结构底表入口。

按主 Skill 完成语言编辑：保留有效论述和条件，删除重复、防御性解释及无信息套话；篇幅由问题决定，不为缩短而删掉推理。

## 4. 完成摘要与全篇核对

正文完成后再提炼摘要，保证摘要只包含正文已支持的发现。结论说明这些发现对读者的意义；真实风险、观察条件随相关判断交代，不机械另加免责声明。

在主 Skill 通用审校之外，核对：

- 标题、摘要、各章和结论共同支持报告主线，后半部分没有漏写或缩水。
- 同一主体、期间、单位、口径及数字跨章一致；行业、产品、场景和公司范围没有混称。
- 关键判断、计算与案例仍能找到来源和附件；章节、表图与引用编号一致。
- 已采用的分析内容保留完整，重复材料已经合并；内部审核过程没有混入客户正文。

## 5. 交付完整文本

默认交付一份可编辑 Markdown；用户只要对话成稿时直接给完整正文。内容按题包含标题与日期、摘要、必要范围说明、主体分析、结论及含义、参考资料和必要附录，不固定为八章。方法、样本或口径说明放在有助于理解的位置，避免多处重复。

文件沿用用户或项目命名规范；无另行约定时使用 `YYYYMMDD_研究主题_文本报告_CO.md`。无待核实事项时不另造空清单。后续仅在用户要求分页或视觉报告时，再进入相应制作流程。
